0 · Por onde começar

Se só tiveres 10 minutos, fica-te por estas 6 prioridades — ordenadas por impacto. Clica para ir direto ao bloco. O resto do guia fica para quando precisares.

  1. 1CavemanobrigatórioCorta drasticamente os tokens de output do Claude Code.
  2. 2CodeBurnobrigatórioAcompanha o custo/tokens gastos por projeto e modelo.
  3. 3Context7recomendadoDocumentação sempre atualizada diretamente no contexto.
  4. 4Chrome DevToolsrecomendadoDebug e performance no Chrome real.
  5. 5Skills de desenvolvimentorecomendadoArquitetura, TDD e produtividade num só bloco de comandos.

1 · Pré-requisitos

Confirma que tens as ferramentas base antes de instalar o resto. Os comandos abaixo apenas verificam a versão — se algum falhar, instala essa ferramenta primeiro.

Verificar o que já tens

Corre num terminal (PowerShell ou Bash). Cada linha deve devolver uma versão.

# Node.js 20+ (necessário para servidores MCP)
node --version
npm --version

# Claude Code CLI
claude --version
Falta o Claude Code? Instala com npm install -g @anthropic-ai/claude-code e autentica com claude (segue o login no browser).

Caveman obrigatório

Faz o Claude Code responder em estilo comprimido ("caveman" — sem artigos, sem palavras de preenchimento, telegráfico) para cortar drasticamente os tokens de output, mantendo código, paths e URLs intactos. Instala-se uma vez, globalmente — fica ativo em todas as conversas, em todos os projetos.

claude plugin marketplace add JuliusBrussee/caveman
claude plugin install caveman@caveman
Confirmar que ficou ativo: abre o Claude Code, escreve /caveman e confirma respostas curtas, ou verifica [CAVEMAN] a laranja na statusline.

Ponytail obrigatório

Plugin que força a solução mais simples que funciona — questiona se a tarefa precisa mesmo de existir (YAGNI), prefere stdlib/nativo a dependências novas, e corta abstrações especulativas antes de escrever código. Complementa o Caveman: aquele comprime a resposta, este comprime a solução.

claude plugin marketplace add DietrichGebert/ponytail
claude plugin install ponytail@ponytail
Confirmar que ficou ativo: escreve /ponytail-help ou verifica [PONYTAIL] na statusline.

Codex (plugin) recomendado

Liga o Codex CLI da OpenAI ao Claude Code como sub-agente de resgate — usa-se quando o Claude fica bloqueado 2× seguidas na mesma tarefa (debugging teimoso, segunda opinião de implementação). Não substitui o fluxo normal, é só para quando este empanca.

claude plugin marketplace add openai/codex-plugin-cc
claude plugin install codex@openai-codex
Instável em sandbox Windows — evita modo autónomo, corre em conversa interativa. Se falhar, aplica o fix diretamente em vez de insistir.

CodeBurn obrigatório

Dashboard local (terminal) que lê os logs de sessão e mostra custo/tokens gastos por projeto, modelo e tarefa, em 31 ferramentas diferentes (Claude Code, Cursor, Codex, Gemini…). Corre 100% local — sem API key, nada sai da máquina. Usa-se para acompanhar o gasto em IA por projeto/cliente da CriativaTek.

npx codeburn
Corre em qualquer pasta — não precisa de instalação prévia nem de estar dentro de um projeto específico.

Orquestração de modelos obrigatório

Configura o Claude Code para delegar automaticamente a subagentes com o modelo certo para cada tipo de tarefa — pesquisa rápida em Haiku, implementação em Sonnet, decisões difíceis em Opus, revisão final em Fable — em vez de correr tudo no modelo principal. Reduz custo (tarefas simples não gastam Opus/Fable) e melhora a qualidade (a revisão final usa sempre um modelo independente e forte).

  1. Criar os 4 subagentes — global, uma vez

    Corre num terminal Bash (Git Bash no Windows, ou Terminal no macOS/Linux). Fica disponível em todos os projetos.

    mkdir -p ~/.claude/agents

cat > ~/.claude/agents/explorer.md <<'MD'
---
name: explorer
description: Usa proativamente este agente para procurar ficheiros, localizar referências, mapear dependências, compreender a estrutura do projeto e recolher contexto sem alterar código.
model: haiku
effort: low
tools: Read, Glob, Grep
maxTurns: 25
---
Explora rapidamente o projeto e devolve apenas informação concreta e relevante.
Não escrevas nem alteres código.
MD

cat > ~/.claude/agents/implementer.md <<'MD'
---
name: implementer
description: Usa proativamente este agente para implementar funcionalidades, corrigir problemas, refatorar código, criar testes e concluir tarefas normais de desenvolvimento.
model: sonnet
effort: medium
permissionMode: acceptEdits
maxTurns: 100
---
Implementa a solução de forma autónoma e consistente com a arquitetura existente.
Não interrompas para pedir confirmação sobre decisões técnicas reversíveis.
MD

cat > ~/.claude/agents/architect.md <<'MD'
---
name: architect
description: Usa proativamente este agente antes de decisões de arquitetura, alterações entre vários módulos, migrações importantes, integrações complexas, problemas de desempenho ou erros cuja causa não seja evidente.
model: opus
effort: high
tools: Read, Glob, Grep, Bash
disallowedTools: Write, Edit
maxTurns: 50
---
Age como arquiteto de software sénior — analisa causa raiz, impacto entre módulos, riscos e alternativas.
Produz uma recomendação concreta para o agente implementador. Não alteres diretamente os ficheiros.
MD

cat > ~/.claude/agents/reviewer.md <<'MD'
---
name: reviewer
description: Usa proativamente este agente depois de alterações importantes e antes de considerar o trabalho concluído. Faz uma revisão independente e profunda da implementação.
model: fable
effort: high
tools: Read, Glob, Grep, Bash
disallowedTools: Write, Edit
maxTurns: 60
---
Faz uma revisão final independente — funcionalidade, segurança, desempenho, testes, casos limite.
Apresenta problemas concretos com prioridade. Não alteres diretamente os ficheiros.
MD
    SubagenteModeloEffortQuando é usado
    explorerHaikulowPesquisas rápidas — ficheiros, referências, dependências
    implementerSonnetmediumEscrever código, testes, corrigir erros
    architectOpushighDecisões de arquitetura, bugs difíceis
    reviewerFablehighRevisão final antes de dar por concluído

  2. Dizer ao Claude Code quando usar cada um — CLAUDE.md global

    Acrescenta isto a ~/.claude/CLAUDE.md (cria o ficheiro se não existir). Não apagues o que já lá tiveres — só acrescenta ao fim.

    ## Orquestração de modelos

Trabalha autonomamente até o objetivo estar concluído. Usa os subagentes especializados
em `~/.claude/agents/` conforme o tipo de tarefa, em vez de fazer tudo com o modelo principal.

## Equipa

| Subagente | Modelo | Effort | Quando usar |
|---|---|---|---|
| `explorer` | Haiku | low | Pesquisas rápidas — localizar ficheiros, referências, dependências, mapear a estrutura do projeto. Não altera código. |
| `implementer` | Sonnet | medium | Escrever código, editar ficheiros, criar/atualizar testes, corrigir erros encontrados. |
| `architect` | Opus | high | Antes de decisões de arquitetura, alterações entre vários módulos, migrações importantes, integrações complexas, problemas de desempenho, ou quando a causa de um erro não é óbvia. Só analisa — não altera ficheiros. |
| `reviewer` | Fable | high | Depois de alterações importantes, antes de dar o trabalho por concluído. Revisão final independente. Só analisa — não altera ficheiros. |

## Regras de delegação

- Usa `explorer` para qualquer pesquisa ou levantamento de contexto antes de escrever código.
- Usa `architect` antes de decisões estruturais ou quando a abordagem não é óbvia — não avances com uma mudança grande sem passar por aqui primeiro.
- Usa `implementer` para o trabalho de implementação em si.
- Usa `reviewer` antes de fechar qualquer tarefa não-trivial. Depois da revisão, corrige autonomamente os problemas relevantes que encontrar.
- Não peças confirmação para decisões técnicas reversíveis.
- Corre testes, lint e análise estática antes de dar uma tarefa por concluída.
- Termina só quando a implementação estiver funcional e revista.
Reinicia a sessão do Claude Code depois de criar estes ficheiros — o CLAUDE.md só é lido no arranque de cada sessão nova, não a meio de uma conversa já em curso.

GBrain obrigatório

Memória persistente local (RAG) que fica disponível entre sessões e projetos — poupa tokens porque o Claude deixa de precisar de reexplicar contexto ou reler o código todo em cada conversa nova. Pesquisa semântica sobre código e notas via gbrain search / gbrain code-def, registado como MCP para o agente consultar diretamente. Requer o gstack instalado (secção 3).

  1. Correr o assistente de instalação

    Dentro do Claude Code, com o gstack já instalado:

    /setup-gbrain
    Escolhe PGLite local para uso a solo (sem contas, ~30s, cérebro isolado só nesta máquina) — Supabase/remoto só compensam se quiseres partilhar a memória entre várias máquinas ou com a equipa.

  2. Configurar a chave de embeddings

    Necessária para pesquisa semântica — usa uma destas antes de correr o assistente:

    # recomendado para código
export VOYAGE_API_KEY=pa-...

# alternativas
export OPENAI_API_KEY=sk-...
export ZEROENTROPY_API_KEY=ze-...
    Sem nenhuma chave, o /setup-gbrain deixa avançar na mesma (--no-embedding) mas fica sem pesquisa semântica até configurares uma.
Confirmar que ficou ativo: claude mcp list deve mostrar gbrain ✓ Connected. Reinicia o Claude Code para os tools mcp__gbrain__* ficarem disponíveis.

Sem resultados nesta secção — tenta outro termo ou limpa os filtros.

2 · Servidores MCP

MCP (Model Context Protocol) liga o Claude a ferramentas externas — ficheiros, documentação, browser, base de dados. Instala-se com claude mcp add. Usa -s user para ficar disponível em todos os projetos, ou -s project (gera .mcp.json partilhável) só neste.

Sintaxe geral: claude mcp add <nome> [opções] -- <comando> para servidores locais, ou claude mcp add --transport http <nome> <url> para remotos.

Laravel Boost só para Laravel

Servidor MCP oficial do Laravel. Dá ao Claude conhecimento das rotas, modelos, migrations, config e docs da versão exata que usas.

# corre na raiz do projeto Laravel
composer require laravel/boost --dev
php artisan boost:install

Context7 recomendado

Injeta documentação atualizada de qualquer biblioteca (Tailwind, Vue, React, Laravel, Node…) diretamente no contexto. Acaba com respostas baseadas em versões antigas.

claude mcp add --transport http context7 https://mcp.context7.com/mcp -s user

GitHub útil

Ler/abrir issues e PRs, navegar repositórios e rever código direto do GitHub. Requer um token (cria um PAT aqui).

claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  -H "Authorization: Bearer SEU_GITHUB_TOKEN" -s user

MySQL recomendado em projetos com BD

Liga o Claude diretamente à base de dados do projeto — inspecionar tabelas, correr queries de leitura. Define as credenciais da tua BD local.

claude mcp add mysql -s project \
  -e MYSQL_HOST=127.0.0.1 -e MYSQL_PORT=3306 \
  -e MYSQL_USER=root -e MYSQL_PASS= -e MYSQL_DB=nome_da_bd \
  -- npx -y @benborla29/mcp-server-mysql
Aponta para a BD local, nunca produção. De preferência usa um utilizador só de leitura para evitar escritas acidentais.

Sentry produção

Deixa o Claude ver erros e issues de produção para diagnóstico. Autentica via OAuth no browser ao ligar.

claude mcp add --transport http sentry https://mcp.sentry.dev/mcp -s user

Playwright recomendado

Controla um browser real — abrir páginas, clicar, preencher formulários e tirar screenshots. Ótimo para validar UI e backoffice.

claude mcp add playwright -s user -- npx -y @playwright/mcp@latest

Chrome DevTools recomendado

Oficial da equipa do Chrome. Complementa o Playwright: onde o Playwright serve para automação/testes E2E, este é para debugging e performance — grava traces de performance, corre auditorias Lighthouse, inspeciona pedidos de rede, tira heap snapshots de memória e lê a consola, tudo no Chrome real.

claude mcp add chrome-devtools -s user -- npx -y chrome-devtools-mcp@latest
Não precisa de API key. As ferramentas de performance enviam opcionalmente URLs à Google CrUX API — para desativar, acrescenta --no-performance-crux ao fim do comando acima.

Firecrawl recomendado

Web scraping e crawling estruturado — extrai páginas em markdown/JSON, rastreia sites inteiros (crawl, map), tira dados estruturados com LLM (extract) e até lê PDFs. Diferente do WebFetch nativo (uma página, resumida): aqui é o site todo, com dados limpos e reutilizáveis. Útil para ingerir documentação externa, concorrência ou conteúdo para as skills de marketing.

claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp -s user
Tier gratuito: scrape, search e interact funcionam sem API key (com rate-limit). Para crawl, extract e monitor precisas de uma API key — usa o endpoint https://mcp.firecrawl.dev/SEU_API_KEY/v2/mcp em vez do de cima.

21st.dev recomendado

Busca semântica sobre uma biblioteca curada de componentes React/Tailwind, temas e templates reais (21st.dev/community/components), mais lookup de logos SVG por nome. Serve para o agente ver referências reais antes de escrever UI nova, em vez de inventar do zero — é o antídoto directo para o «AI slop» visual. Complementa o UI/UX Pro Max (secção 3): aquele dá guidelines e paletas, este dá componentes já feitos.

claude mcp add --scope user --transport http 21st https://21st.dev/api/mcp --header "x-api-key: SUA_CHAVE"
Tier gratuito: busca semântica e lookup de logos são ilimitados; instalar código de componentes está limitado a 2 por dia. Pro ($20/mês) só é preciso se bateres nesse limite com frequência. Chave em 21st.dev/settings.
A chave fica em claro no ~/.claude.json — não commitar esse ficheiro. Para componentes shadcn continua a usar o MCP oficial do shadcn (grátis, sem limite de instalações).

shadcn recomendado

Dá ao agente acesso directo ao registo do shadcn/ui: listar componentes, blocos e templates, procurar por nome ou função, e instalar em linguagem natural («adiciona um formulário de login»). Sem API key e sem limite de instalações — é o par natural do 21st.dev acima: 21st para descobrir referências, shadcn para instalar.

# corre na raiz do projeto (precisa de components.json)
npx shadcn@latest mcp init --client claude
Ao contrário dos MCP acima, este é por projeto — escreve o .mcp.json na raiz e lê os registos de components.json. Repete o comando em cada projeto que use shadcn. Registos privados autenticam-se por variáveis em .env.local.

Browser Tools recomendado

Screenshots, consola, erros de rede e auditorias (acessibilidade, performance, SEO, boas práticas) diretamente do browser real — mais leve que o Chrome DevTools MCP para checks rápidos de QA visual.

claude mcp add browser-tools -s user -- npx -y @agentdeskai/browser-tools-mcp@latest

Higgsfield opcional — conteúdo

Geração de imagem e vídeo AI a partir do agente — Veo 3, Kling 3.0, Nano Banana Pro e outros modelos, num único endpoint. Para criativos de anúncios, b-roll, product shots e motion. Não é uma ferramenta de programação: só interessa a quem trabalha em marketing/conteúdo.

claude mcp add --scope user --transport http higgsfield https://mcp.higgsfield.ai/mcp
Sem API key — autentica por OAuth no browser à primeira utilização. Corre /mcp → higgsfield → Authenticate, e reinicia a sessão. Tier gratuito: 10 créditos/dia. Planos desde $15/mês (200 créditos); Plus $39/mês (1.000) para volume a sério. Referência de custo: Veo 3 de 8s com áudio ≈ 58 créditos, Kling 3.0 de 8s a 720p ≈ 14.
Se já o tiveres adicionado como connector no claude.ai, não corras o comando acima — ficam dois registos do mesmo servidor e é fácil autenticar um e ver o outro a falhar. Escolhe um só.

Filesystem opcional

Acesso de leitura/escrita a uma pasta específica fora do projeto atual (ex.: partilhar ficheiros entre projetos). Substitui D:\HERD abaixo pelo caminho da pasta que queres partilhar.

claude mcp add filesystem -s user -- npx -y @modelcontextprotocol/server-filesystem D:\HERD

Sequential Thinking opcional

Dá ao Claude um espaço estruturado para raciocínio passo-a-passo em problemas complexos (modelação de dados, máquinas de estados, arquitetura).

claude mcp add sequential-thinking -s user -- npx -y @modelcontextprotocol/server-sequential-thinking
Depois de adicionar: reinicia o Claude Code e corre claude mcp list para confirmar o estado ✓ connected de cada servidor.

Sem resultados nesta secção — tenta outro termo ou limpa os filtros.

Graphify recomendado em codebases grandes instalação diferente

Constrói um knowledge graph do projeto (código, schemas SQL, scripts, docs, diagramas) e ensina o Claude a consultar o grafo antes de fazer grep ficheiro a ficheiro — reduz drasticamente os tokens gastos a explorar codebases grandes. Não segue o padrão npx skills add acima: é uma ferramenta Python, instalada à parte, em dois passos distintos.

Como funciona: instala-se a ferramenta uma vez, de forma global (fica disponível em todos os projetos). Depois, em cada projeto onde a queiras usar, corre-se o comando que gera o grafo — o resultado fica gravado dentro desse próprio repositório.

  1. Instalar a ferramenta — uma vez, global

    Escolhe um gestor de pacotes Python. uv é o recomendado pelo projeto.

    # instalar o CLI (escolhe um)
uv tool install graphifyy
# pipx install graphifyy
# pip install graphifyy

# registar a skill no Claude Code, Cursor, etc.
graphify install
    Isto liga o comando /graphify no Claude Code. Se graphify não for reconhecido depois de instalar com uv, corre uv tool update-shell e reabre o terminal.

  2. Gerar o grafo — dentro de cada projeto

    Dentro do Claude Code, na raiz do projeto que queres mapear:

    /graphify .

# para atualizar só os ficheiros que mudaram, usa:
# /graphify . --update
    Faz commit da pasta graphify-out/ ao repositório (exceto graphify-out/cost.json, que é só local) — assim toda a equipa arranca com o mesmo mapa em vez de o gerar cada um por si.
Ficheiro geradoPara quê
graphify-out/graph.htmlVisualização interativa do grafo (abrir no browser)
graphify-out/GRAPH_REPORT.mdResumo dos conceitos-chave e perguntas sugeridas
graphify-out/graph.jsonDados do grafo, para consulta programática

Browser Harness recomendado instalação diferente

Liga o Claude diretamente ao teu Chrome real via CDP (Chrome DevTools Protocol), sem abstração — quando falta alguma capacidade, é o próprio agente que escreve o código necessário em runtime e vai guardando "skills" por site (fluxos, seletores). Complementa o Playwright/Chrome DevTools MCP: usa-o quando esses se arrastam em sites difíceis ou fluxos muito específicos. Também não segue o padrão npx skills add — instala-se via Python (uv).

Como instalar: cola este pedido diretamente numa conversa do Claude Code (não é um comando de terminal): 
Instala ou atualiza o browser-harness para a versão estável mais recente com uv usando
Python 3.12, regista a skill a partir de `browser-harness skill`, e liga-o ao meu browser.

Depois, ativa o modo remoto de debug no Chrome e aceita a ligação quando pedido.

Não precisa de API key para uso local (liga-se diretamente ao teu Chrome via --remote-debugging-port). Existe uma cloud opcional da Browser Use (tier gratuito, 3 browsers em simultâneo) só se precisares de correr sem Chrome local.

gstack recomendado instalação diferente

Suite grande de skills para todo o ciclo de engenharia com IA — browser headless rápido (/browse, mais leve que Playwright/Chrome DevTools MCP para QA e dogfooding), revisão de planos por perfis (CEO, design, eng, devex), ship/deploy (/ship, /land-and-deploy, /canary), debugging sistemático (/investigate), pentesting autónomo (/shannon) e uma memória persistente local (/setup-gbrain) que o browser e as outras skills gstack consultam entre sessões. Um repositório, um instalador.

git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack
cd ~/.claude/skills/gstack && ./setup
Sobrepõe-se ao Playwright MCP e ao Browser Harness acima para tarefas de browser — usa o gstack para QA/dogfooding rápido do dia a dia, e Playwright/Browser Harness quando precisas de testes E2E formais ou de um site que resiste à automação normal.
